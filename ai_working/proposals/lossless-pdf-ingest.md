# Lossless PDF Ingest Workflow

**Problem**: Current Gemini extraction extracts *learnings/concepts* thematically, losing the original text flow. Re-extraction with different domain interests requires re-running expensive Gemini.

**Solution**: Two-phase ingest - Gemini for full-text extraction, local processing for domain-specific learnings.

---

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────────┐
│                     PHASE 1: GEMINI FULL-TEXT                   │
│                    (One-time, expensive)                        │
├─────────────────────────────────────────────────────────────────┤
│  PDF → Gemini → Full-text Markdown with page markers            │
│                                                                 │
│  Output: ~/switchboard/{domain}/sources/{book}/_full-text.md    │
│          ~/switchboard/{domain}/sources/{book}/_book-info.md    │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                  PHASE 2: LOCAL EXTRACTION                      │
│              (Repeatable, cheap, domain-aware)                  │
├─────────────────────────────────────────────────────────────────┤
│  Full-text.md → Claude SDK → Domain-specific learnings          │
│                                                                 │
│  • Can re-run with different domains                            │
│  • Full citations always available                              │
│  • Cheaper than Gemini                                          │
│                                                                 │
│  Output: ~/switchboard/{domain}/sources/{book}/learnings/       │
│          └── {domain}-insights.md                               │
│          └── {domain}-concepts.md                               │
│          └── {domain}-relationships.jsonl                       │
└─────────────────────────────────────────────────────────────────┘
```

### Command

```bash
# Extract learnings from full-text using local Claude

# Re-run with different domain focus
make knowledge-extract-learnings SOURCE=~/switchboard/chanoyu/sources/suzuki-zen-japanese-culture DOMAINS=poa
```

### Benefits

1. **Reusable source material** - Full text always available
2. **Multi-domain extraction** - Same book, different lenses
3. **Cost efficiency** - Gemini once, Claude many times
4. **Perfect citations** - Can always verify against full-text
5. **Incremental updates** - Add new domains without re-ingesting

## Gemini Full-Text Prompt (Draft)

```
You are a precise text transcription specialist. Your task is to create a
complete, lossless markdown transcription of this PDF book.

## CRITICAL REQUIREMENTS

### 1. Page Markers (MOST IMPORTANT)
- Insert `<!-- PAGE: n -->` marker at the start of each page
- Every page boundary must be marked
- Page numbers enable precise citations

### 2. Complete Transcription
- Transcribe ALL text, not just "key points"
- Preserve paragraph structure
- Maintain heading hierarchy (use #, ##, ###)
- Keep original punctuation and formatting

### 3. Japanese/Original Language Text
- Preserve ALL kanji, hiragana, katakana exactly as written
- Add romaji in parentheses for specialized terms
- Format: 茶道 (chadō)

### 4. Tables and Lists
- Recreate tables in markdown format
- Preserve numbered and bulleted lists
- Maintain original ordering

### 5. Quotations
- Use blockquote (>) for quotations
- Preserve quotation attribution

### 6. Figures and Images
- Insert placeholder: [Figure: description of image]
- Note any captions
- Do not describe images in detail, just note their presence

### Extraction Process

1. Read `_full-text.md` from source directory
2. Chunk by page markers or heading boundaries
3. For each chunk, extract with domain-specific prompt
4. Aggregate and deduplicate concepts
5. Generate:
   - `learnings/{domain}-insights.md` - Human-readable summary
   - `learnings/{domain}-concepts.md` - Key concepts with page refs
   - `learnings/extractions.jsonl` - Structured for knowledge graph

### Chunking Strategy

```python
def chunk_by_pages(full_text: str, pages_per_chunk: int = 10) -> list[str]:
    """Split full text by page markers."""
    import re

    # Split on page markers
    pages = re.split(r'<!-- PAGE: (\d+) -->', full_text)

    # Recombine with page numbers preserved
    chunks = []
    for i in range(0, len(pages), pages_per_chunk * 2):
        chunk_pages = pages[i:i + pages_per_chunk * 2]
        chunks.append(''.join(chunk_pages))

    return chunks
```

## Migration Path

### Existing Sources

For already-extracted books (like Suzuki), can optionally:
1. Keep existing thematic extractions as-is
2. Add full-text later when re-reading PDF
3. Use existing extractions for knowledge graph

### New Sources

For new books:
1. Use `gemini-fulltext-prompt` first
2. Save full-text to source directory
3. Run `extract-learnings` with desired domains
4. Add additional domains later as needed

## Benefits Summary

| Aspect | Current | Enhanced |
|--------|---------|----------|
| Source preservation | Thematic excerpts only | Full lossless text |
| Re-extraction cost | Full Gemini re-run | Local Claude only |
| Multi-domain | Requires re-upload | Just re-run extraction |
| Citation accuracy | Page markers inline | Full text + markers |
| Storage | ~5-10 files per book | 2 core + learnings |
| Flexibility | Fixed at extraction time | Infinite re-extraction |
